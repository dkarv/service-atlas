## Notes

Generated by `./run.sh --runs 3 --startup-runs 40`, only this section is written by hand.

- **Kotlin native vs. Go:** startup is on par, idle RAM is mostly the larger binary mapped into memory (file-backed pages that can be evicted). The peak is 42% higher. The cost shows in image size (3.4x) and build time (10x, of which about 25 s is `native-image`).
- **Kotlin native vs. JVM:** Native Image makes the image 7x smaller, startup 4x faster and peak RAM 5x lower, for about 24 s more build time. The warm JVM has the highest throughput thanks to its JIT, which uses runtime profiles. GraalVM Community Edition has no profile-guided optimization, and the branch builds with `-Os` (smaller, less inlining).
- **RAM after the refreshes** is a snapshot right after the last refresh and depends on when the garbage collector ran, which explains Go being above Kotlin native there. Compare the peak instead.
- **API differences** come from `java.net.URI`: it keeps `../` above the root and adds `/` before a bare query. Browsers treat both forms alike. See the README of the Kotlin branches.
- **Code** counts every file a branch adds except docs, so it includes the Dockerfile and build files. The Kotlin port needs more code mostly because the JDK has no equivalent to Go's `embed` and `http.FileServer`.
